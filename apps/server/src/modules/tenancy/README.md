# tenancy module
`TenantScope` (`withTenant`, `withPlatform`, after-commit hooks, F.10), `TenantResolver` (60 second cache, `invalidate`), the C.3 readiness checks (migrations, schema privileges) and the PostgreSQL stores of rate limits (F.3) and idempotency keys (D.1; a claim without a stored response is in progress for a lease of five minutes, then the same request may take it over). Imports `CommonModule` (clock, job queue, notification writer, file responder).
Owner: WP-08.
Milestone 2 (M2-S09): `TenantResolver` subscribes to `TenantChangeListener` of the licence module and drops an organisation on its change notice `mscd_tenant_changed` (every entry after the listener reconnects), so a status change made in any api process or command counts in every api and worker process of multi tenancy within moments.
Milestone 3 (M3-12): `withTenant(ctx, fn, { snapshot: true })` runs a REPEATABLE READ, READ ONLY transaction (set by the statement that starts it, before `set_config`), with an optional `idleTimeoutSeconds` for a reader that works between its statements. `holdSnapshot(fn)` holds one snapshot (`pg_export_snapshot` in a transaction that reads no table, so it holds no table lock) for short transactions that read it with `withTenant(ctx, read, { snapshot: held })`: each sees the same instant and keeps its table locks only until it ends, and one that read a table rewritten after the snapshot fails with `SnapshotTableRewrittenError` instead of showing it empty. The organisation export reads each dataset that way. Idempotency keys of a principal without an organisation (a platform operator) are scoped by user under `PLATFORM_IDEMPOTENCY_ORG`, the nil id no organisation has. A stored answer never holds a one-time link: `idempotentBodyToStore` (`idempotency-secrets.ts`) leaves out the members of `ONE_TIME_SECRET_MEMBERS` (the invitation, password and set-password links that some operator commands answer with when mail is off) and gives the replay a message that says how to get a new link; the token of any other link in a stored answer is replaced by `removed` and logged.
