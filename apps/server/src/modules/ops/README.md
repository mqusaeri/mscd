# ops module

Platform operator endpoints and diagnostics (D.3 Operations), and the metrics of ARCHITECTURE 12 that are read from the job queue and the database.
Owner: WP-34 (skeleton by WP-03, build plan B.4); Milestone 2: M2-06 (organisations, factor reset), M2-S09 (organisation lifecycle), M2-S11, M2-19 (accounts and platform operators).

| Route | Permission | Notes |
|---|---|---|
| `GET /api/v1/ops/health` | `ops.read` | Readiness checks, job queue, job outbox (degraded when rows are stuck or parked), telemetry; newest applied migration of `platform` and `ref`; queue statistics; licence state per active organisation |
| `GET /api/v1/ops/queues` | `ops.read` | `JobQueue.stats()` |
| `POST /api/v1/ops/jobs/{name}/run` | `ops.jobs.run` | Allow-list of D.3 (`OPS_RUNNABLE_JOBS`), body `{org?}` only, empty payload. Tenant jobs need `org` of an active organisation (422 otherwise, 404 for an unknown slug); installation-wide jobs refuse `org` (422); a job without a handler in the build is 422. Singleton key `ops:<job>:<org id or all>`; 409 when the driver reports a run already waiting. The job and the `ops.job_run` entry (platform chain, actor kind `operator`) commit in one transaction |
| `POST /api/v1/ops/diagnostics` | `ops.read` | `.tar.gz` with `README.txt`, `profile.json`, `versions.json`, `migrations.json`, `queues.json`, `health.json`, `logs.ndjson` (ring buffer, at most 1,000 lines) and `metrics.txt`; every file scrubbed by `SecretScrubber`; audited `ops.diagnostics_exported` before the bytes are sent |
| `GET /api/v1/ops/organizations` | `ops.read` | Multi tenancy only (409 `single_tenancy` otherwise). Organisations with status, licence state, plan and validity of the entitlement row, active members (guests not counted), systems that are not archived, verified domains; `q` searches slug and name, `status` filters; paged (M2-06) |
| `POST /api/v1/ops/organizations` | `ops.tenants.manage` | Multi tenancy only. `TenantProvisioner.create` with the api's database owner URL and a data key of the storage gateway (503 when either is missing), local sign-in allowed, the first administrator invited as Tenant Admin and emailed. With `mail.required` and SMTP not answering: 409 `mail_required` before anything is created; the one-time link is returned only when mail is not required and the email did not go out. An existing active account gets the email and the notification `membership_invited`. 409 `org_exists`, 409 `first_admin_disabled`, 422 `unknown_preset`. Audited `ops.organization_created` (M2-06) |
| `GET /api/v1/ops/organizations/{org}` | `ops.read` | Multi tenancy only. Status, region, created date, active members (guests not counted), systems that are not archived, the entitlement summary (plan, source, user and system limits, last valid day; written once from a signed licence installed before M2-S10, as the list does), every email domain with its status, and the time of the last completed sign-in (newest active session of the organisation). 404 for an unknown slug (M2-S09) |
| `POST /api/v1/ops/organizations/{org}/status` | `ops.tenants.manage` | Multi tenancy only. Body `{status, reason, confirmSlug?}`: the machine of J.8 (`organization.status`, rows of this route), 409 `transition-not-allowed` with messageKey `invalid_status_transition` for any other move (the same status included), 422 `business-rule` `confirmation_mismatch` when offboarding or archived lacks `confirmSlug` equal to the slug. One platform-scope transaction: row lock, status, `platform.organization_status_event`, `ops.organization_status_changed` (platform chain, before and after), for `suspended` and `archived` the revocation of every session whose current organisation it is (`OrgSessions`, reasons `organisation_suspended`, `organisation_archived`), and the change notice `mscd_tenant_changed`. After the commit: this process drops its cached organisation; every active Tenant Admin gets the in-app notice and the email `organization_status_changed` (status, meaning, reason; no person named). The answer counts the sessions ended and the admins emailed (M2-S09) |
| `GET /api/v1/ops/organizations/{org}/events` | `ops.read` | Multi tenancy only. The status history, newest first, with the operator's handle and name (null for the command line), paged; 404 for an unknown slug (M2-S09) |
| `POST /api/v1/ops/users/reset-mfa` | `ops.users.manage` | Body `{email, reason}`: removes the factors and recovery codes of the account, clears its second-factor lock, ends its sessions, emails it; 404 when no account has the address or it has no factor. Audited `auth.mfa_reset` with the reason, actor kind `operator` (M2-06) |
| `GET /api/v1/ops/accounts` | `ops.read` | Both tenancy modes. Every account that is not deleted (people, guests, the system account), searched by name, email or handle (`q`), filtered by organisation (`org`), account status and kind, ordered by name, paged. Each row: id, handle, email, name, kind, status, second factor set up, locked now (password or second-factor lock), last sign-in, created, platform operator, memberships (organisation slug and name, membership status, admin roles) and the weak ETag of the row. Never the password hash, factor secrets or business roles (M2-19) |
| `GET /api/v1/ops/accounts/{id}` | `ops.read` | The row, the open sessions (start, last activity, method, state, network cut to /24 or /48 in SQL, browser and system from the user agent by `browserOf`, current organisation; 50 at most, latest first) and the latest 20 `platform.audit_log` entries about the account (entity the account, or an invitation of it), with the reason of operator entries only. 404 `unknown_account` for an unknown account (M2-19) |
| `POST /api/v1/ops/accounts/{id}/reset-mfa` | `ops.users.manage` | Body `{reason}` (3 to 500). As `ops.users.reset-mfa`, through `OperatorAccountsService.resetFactorOf`; 403 `own_account` for the operator's own account (the reset ends every session; the person replaces their own authenticator on My account), 409 `no_second_factor`, 409 `system_account`, 404 `unknown_account`. The reset does not wait for mail: the security email `mfa_reset` is sent after the commit, and `emailed` (and the message) says whether it went out. Audited `auth.mfa_reset` (M2-19) |
| `POST /api/v1/ops/accounts/{id}/password-reset` | `ops.users.manage` | A token of kind `reset` (30 minutes, F.4; older unused ones end) emailed with the template `password_reset`. 409 `guest_account`, `account_not_active` (invited or disabled), `no_membership` (no active organisation and no operator role), `local_login_not_allowed` (no organisation of the account allows local sign-in), `system_account`; with `mail.required` and mail not working 409 `mail_required` before anything is written. The link is in the answer only when mail is not required and the email did not go out. Audited `auth.password_reset` with `step: link_sent` (M2-19) |
| `POST /api/v1/ops/accounts/{id}/invitations/{org}/resend` | `ops.users.manage` | For an `invited` membership: the unused invitations of the membership are revoked, a new one (72 hours) is emailed with the template `invitation`. 404 `unknown_organisation` or `membership_not_found`; 409 `membership_not_invited`, `account_disabled`, `organization_archived`, `mail_required`. Audited `user.invited` (organisation of the membership, entity the invitation, `resent: true`) (M2-19) |
| `POST /api/v1/ops/accounts/{id}/sessions/revoke` | `ops.users.manage` | Ends every open session of the account (reason `operator_revoked`). 403 `own_account` for the operator's own account. Audited `auth.session_revoked` (M2-19) |
| `POST /api/v1/ops/accounts/{id}/status` | `ops.users.manage` | Body `{status: active or disabled, reason}`, optional `If-Match` with the row's ETag (412). `disabled` ends every session (reason `user_disabled`); `active` checks the user limit of each organisation where the account is an active member (422 `LIC-USERS`). 403 `own_account`; 409 `status_unchanged`, `account_invited` (an invited account is neither disabled nor enabled: it becomes active when the person accepts, and can be disabled after that), `last_operator`, `system_account`. A disable locks the active operator accounts before the target (`lockActiveOperators`, the order of the operator removal), so concurrent decisions about the last operator wait for each other. Audited `user.updated` (M2-19) |
| `GET /api/v1/ops/operators` | `ops.read` | Accounts with an active `platform_operator` role: second factor, password set, last sign-in, granted at and by, and `self` for the caller (M2-19) |
| `POST /api/v1/ops/operators` | `ops.users.manage` | Body `{email, name, reason}`; the flow of `admin create-operator` with the operator as `granted_by`, as the database owner (`withOwner`, 503 without `database.migrator_url_file`). 409 `system_account`, `account_disabled`, `already_operator`, `mail_required`. The set-password link is in the answer only when mail is not required and the email did not go out. Audited `ops.operator_created` with the reason (M2-19) |
| `DELETE /api/v1/ops/operators/{id}` | `ops.users.manage` | Body `{reason}`; as the database owner, ends the role and every session (reason `roles_changed`). 403 `own_account`, 409 `last_operator` (the active operator accounts are locked first), 404 `not_operator` when the account holds no active role. Audited `ops.operator_revoked` with the reason (M2-19) |

`OpsMetricsCollector` keeps one snapshot of the collected metrics for 15 seconds, so scrapes of the api and the worker cost one round of queries per interval; a section that fails keeps its last values and is logged once.

`POST /api/v1/ops/organizations` also writes the plan preset of the body (`EntitlementService.applyPreset` of M2-S10, before the invitation) and the region of `tenancy.default_region` (M2-S09). `OpsOrganizationsService` and `OrganizationStatusService` take an `OperatorActor`: the signed-in operator for the routes, `CLI_OPERATOR` (no user) for the commands `tenant list`, `show`, `set-status` and `onboard` of `src/cli/tenant.ts`, which build a command context with these services (`createOpsCliContext`, also used by `mscd-server diagnostics`). `GET /ops/health` lists the migration state as a `down` component when the database cannot be reached, so the offline diagnostics archive still has a health report.

`mail-readiness.ts` checks the SMTP server of the profile (connection, greeting and login) for the mail rule of `ops.organizations.create` and of the commands `admin create-user` and `admin create-operator`. `TenantDataKeys` gives the data key issuer of a new organisation (the storage gateway); a test application replaces it.

`account-support.ts` holds the refusals of the account routes (message keys with English and Indonesian messages), `browserOf`, `withOwner` (one owner transaction with platform scope, as `admin create-operator` uses) and `revokeAllSessions`. `OperatorsService.add` repeats the steps of `adminCreateOperator` of `src/cli/admin.ts` with the operator as actor and `granted_by`; the command keeps its own copy until it is moved onto the service.
