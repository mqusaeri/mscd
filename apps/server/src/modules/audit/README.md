# audit module
`AUDIT_WRITER` for `platform.audit_log` and every tenant `audit_trail` (changed fields only, F.11 redaction, edition lookup), `AuditChainVerifier` with anchor comparison, the anchor signing and verification helpers (D-33), and the four `/admin/audit-trail` routes.
Owner: WP-08; the anchor job is WP-22.
Milestone 3 (M3-12): the anchor checks (the verifier and `audit.verify-chain`) trust `trustedAnchorKeys` of `anchor-keys.ts`: the keys compiled into the build, the public half of `audit.anchor_key_file` where the process can read it (the worker), and every public key of the `.pub` file beside it (`secrets/audit-anchor.pub` beside `secrets/audit-anchor.key`). That file holds the installation's current public anchor key and, after the key was replaced, the earlier ones as further PEM blocks, so older anchors keep verifying. A process without the private key (the api) trusts the installation's keys only through that file, so the deployment must give the api and the worker `audit-anchor.pub`; a process that can use neither file logs a warning when it starts. Keys never come from the database.
