## Review round: minor findings

| # | Finding | Change |
|---|---|---|
| 1 | The vault guard never protected a copy of 100 objects or fewer: with an empty vault and a copy of 60 objects the count check passed and `--max-delete 100` let rclone delete all 60, while `backup-restore.md` said an empty vault never empties the copy | `cmd_vault` (`backup-run.sh`) stops before anything changes when the vault holds fewer objects than the copy by more than a tenth of the copy, whatever the size of the copy (an empty vault always). The app deletes a vault object only when its own upload failed (at once, in the same request), and the purge of K.8 will delete the objects of an organisation, so a normal night deletes none. `MSCD_BACKUP_MAX_DELETE` sets this limit and rclone's (`-1` from `--allow-vault-deletes`: none); without it rclone's `--max-delete` stays a tenth of the copy with at least 100, as a second stop for deletions that new objects hide in the counts. `restore-test.sh --local` now also empties the vault and checks that the default limits stop the sync. `backup-restore.md` (the nightly backup, Troubleshooting, Tests) and the header of `backup.sh` say what the guard does |
| 2 | A failed build of the backup tools image during a deploy showed only the generic WARN line: `deploy-check` printed the build lines indented, and `backup_setup` of `saas-deploy.sh` passes on PASS, INFO and WARN lines only; the lines were also the Dockerfile context at the end of the log, not the reason | `deploy-check` (`backup.sh`) prints the reason as `INFO  Image build: ...` lines (at most 6, without colour codes, organisation schema names and email addresses hidden). `bk_image` (`lib.sh`) prints the output of the failed build step, which BuildKit repeats with a time in front (such as `apk could not install restic=...` and `breaks: world[restic=...]`), else the end of the log without the Dockerfile lines. The PASS line of `deploy-check` also reads the image line when the output has colour codes. Checked by hand on a copy of the release whose `RESTIC_PKG_VERSION` names a build Alpine does not have: through the filter of `backup_setup` the deploy shows the WARN line, `ERROR: unable to select packages`, the `breaks:` line and the `apk could not install` message. `saas-deploy.sh` is unchanged |
| 3 | The rehearsal ran `saas-deploy.sh` and `backup.sh status` with `env -i` and without `MSCD_BUILD_CA`, so behind a TLS-inspecting proxy the backup tools image could not be built there (R-12) | `saas-rehearsal.sh` (assigned edit, see the table above): a copy of the CA that the deploy user can read, passed in both `env -i` lists. Not run here: this host has no proxy, and the rehearsal itself is the orchestrator's (Follow-ups) |
| 4 | No test ran `restore-test.sh --ci` as a user that is not root, which is how `restore-test.yml` runs it on a GitHub-hosted runner | `check_ci` of `--local` runs `--ci` with `setpriv` as the test owner of the off-site values (uid 61007) in the group of the Docker socket, with `env -i` and the variables of the workflow step, from a copy of `deploy/` that this user can read (without `config/demo-secrets`); then the same user removes the work folder, as the clean-up step of the workflow does. It now writes the file at 0600, then sets 0400, and fails with a clear line when the copy fails |
