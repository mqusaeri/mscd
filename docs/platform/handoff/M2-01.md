# M2-01 handoff: web screen host and Administration area

M2-01 builds section C of `docs/platform/MILESTONE-2.md` once for every later web package: host slots in the generated views, the screen registry, the host glue in the controller, the host context, the UI kit, action claims and detail extensions, and the test plumbing. It adds the reference screen "Licence", the administration landing for Tenant Admins and Storage Admins without a business role, the role labels of every business role, the "Internal progress score" label of the readiness block, the clause group of the Controls screen and the permission checks of Reassign, Change due date and Send reminder.

## What was built

### Host slots in the generated views (C.1)

`apps/web/scripts/convert-template.mjs` has a new block of `PATCHES` ("Milestone 2 host slots"). `project/MSCD Mockup.dc.html` is unchanged; the views were regenerated with `npm run gen:views -w @mscd/web` (`AppView`, `Drawer`, `DrillScreen`, `Overview`, `PageDetail`, `Portfolio`, `Timeline` and `TopBar` changed; `hover.css` did not).

| `hostLayer` | the `.mscd` root before the toast (portals of host modals and drawers) |
| `hostDetail` | the end of the drawer body in the `Drawer` split and the `PageDetail` split |
| `hostTopbar` | the top bar before the role menu button |
| `row.det.hostExt` | the end of an inline row detail (drill mode `inline`) |

## Deviations

1. More slots than the four of C.1: the inline row detail, the timeline event, preparation and cycle items, and the system switcher wrapper. Detail extensions of the kinds `event`, `prep` and `cycle` and the inline drill mode need a place, and the no-system path needs to hide the switcher.
2. `meta.json` also carries `scope`, `perm` and `nav`. The E2E helpers compute the API sidebar from `GET /me` with them; `registry.test.tsx` checks they match `index.tsx`.
3. The sample opener takes `?persona=<role>` next to `?screen=<id>`. Without it the controller switches to the first persona in `roles` when the current one cannot open the screen. With it, a screen that persona cannot open is ignored and the persona lands on its own first screen (My Tasks for the Domain Owner, the portfolio for the others), as after a persona switch. Both parameters are ignored in API builds.
4. The Licence adapter is chosen in `Screen.tsx` (`adapterFor`) instead of `index.tsx`, with the same `import.meta.env.VITE_DATA_SOURCE === 'api'` test. `index.tsx` is loaded eagerly by the registry, so a choice there would put the api adapter in the main bundle; `Screen.tsx` is the lazy chunk of the screen. The sample adapter comes through a dynamic import in the sample branch.
5. Page actions get the host context and no component state, so "Install licence" opens its dialog through `ctx.go('license', { params: { install } })`, which the screen reads from `ctx.params`.
6. Sample mode has no permission data, so host screens check sample persona grants in `host.tsx` (`SAMPLE_GRANTS`): `manager` holds every permission, `top`, `auditor` and `owner` a short list of the rights their role has in the F.6 matrix. API mode uses `GET /me`.
7. `controller.test.ts`: the API fixture grants `reminder.send` in ISMS so the reminder test still finds Send reminder, which C.5 now hides without the permission.
8. `call()` takes the `[method, path]` constants of a screen's `routes.ts` (R-17) instead of a route id; `ROUTE_IDS` and the contract test keep the link to the route table.
9. The browser error check of `e2e/helpers.js` no longer counts a GET (other than a page load) that a later page load of the same test cut off. Host screens load their chunk and read their data after they open, unlike the generated screens that read the whole snapshot first, so a walk that loads the next page while the Licence read or chunk is under way aborted it (`requestfailed: /api/v1/license` in the Indonesian walk of the API project, `requestfailed: /assets/Screen-*.js` and a font file in the sample project under load). Every other failed request still fails the test.
10. `e2e/api-only/admin-landing.spec.js` expects the first administration screen the session may open, read from `meta.json` and `GET /me`, so it keeps passing when M2-16 adds "Getting started" before Licence.

No dependency was added.
