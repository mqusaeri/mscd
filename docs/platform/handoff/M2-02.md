# M2-02 handoff: server contract, schema and permissions

M2-02 writes the whole Milestone 2 contract for both tracks in wave 1a: the 38 new routes of D.1 with schemas, examples and OpenAPI output, the D.2 changes on existing routes, D.3 in full (tenant migration 0008, platform migration 0005, Kysely types, enums, permissions, machines, profile keys, sub-modules, stub jobs, CLI placeholders), the plan-anchored shared tests and the split sweep data that later packages fill. Every new route is mounted with a stub that answers 501 `not-implemented` after the guard. No Milestone 1 route answers differently, with the two exceptions listed under deviations 7 and 8.

6. M2-08: `imports.commit` has `ms.read` in the guard (J.1); the service must check the permission of the kind again.
7. Every building package deletes its `m2-pending` file when its stubs are gone, and fills its `security/record-tables/M2-*.ts` and `rbac/expectations/M2-*.ts`.
8. For the orchestrator (outside the Owns list of M2-02, Milestone 1 code): `GET /admin/audit-trail/export` (`modules/audit/audit-trail.controller.ts`) starts the CSV query (`body: this.trail.exportCsv(...)`) before `files.send` writes the `file.downloaded` entry. On a busy machine the file can miss its own download entry, and `test/int/platform/audit.test.ts` "exports a system as formula-safe CSV" then fails (it passes alone). Passing a function that starts the query after the audit write would remove the race.
9. M2-S09, M2-S10, M2-S11: write `platform.verified_domain`, `platform.entitlement`, `platform.organization_status_event` and `organization.status` in platform scope: in a transaction opened with `scope.withPlatform`, or inside an organisation transaction wrapped in `inPlatformScope(trx, fn)` (`identity/platform-scope.ts`). This covers the operator routes, the jobs `entitlement.expiry` and `domain.verify`, the CLI commands, and two M2-S10 writes that do not run on an operator route: `admin.license.put` in multi tenancy (Tenant Admin, `license.manage` at organisation scope), which writes the entitlement row with source `signed_licence` inside `scope.withTenant` in `license/licence.service.ts`, and the backfill of a missing entitlement row by `LicenceService` on the first read (M2-S10 brief). In an organisation-scoped transaction of the app role these tables are read only: an insert fails with SQLSTATE 42501, an update or delete changes no row, and a status change raises 42501.
10. For the orchestrator (Milestone 1 code, outside the Owns list): `test/int/jobs-health/link-health.test.ts` "checks every file reference of the system as one background task" reads the new task right after `POST /ms/{ms}/link-health/run` and expects `queued`. In one full run on the busy build host the task was already `running`. The test passes alone (twice). Accepting `queued` or `running` at that point would remove the race.
