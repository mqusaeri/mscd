# M2-02 handoff: server contract, schema and permissions

M2-02 writes the whole Milestone 2 contract for both tracks in wave 1a: the 38 new routes of D.1 with schemas, examples and OpenAPI output, the D.2 changes on existing routes, D.3 in full (tenant migration 0008, platform migration 0005, Kysely types, enums, permissions, machines, profile keys, sub-modules, stub jobs, CLI placeholders), the plan-anchored shared tests and the split sweep data that later packages fill. Every new route is mounted with a stub that answers 501 `not-implemented` after the guard. No Milestone 1 route answers differently, with the two exceptions listed under deviations 7 and 8.

## Deviations

1. Edits outside the Owns list, each needed to compile or to keep Milestone 1 tests green after the contract change:
   - `apps/server/src/common/api-route.ts`: `DELETE` in the method map (`ops.domains.remove`).
   - `apps/server/src/common/problems.ts`: title of `not-implemented`, `NotImplementedError`, `routeStub()`.
   - `apps/server/src/common/jobs/job-payloads.ts`: payload types of the six new jobs (the map has a compile-time completeness check).
   - `apps/server/src/modules/rules/messages.ts`: messages of `APPL-ASSESS`, `PACK-ROW-REMOVED`, `AUD-INDEP` (completeness check).
   - `apps/server/src/modules/risk-registers/registers.service.ts`: field lists for the two new register kinds and the 501 until M2-07.
   - `apps/server/src/modules/packs/packs.module.ts`: registers the stub `ApplicabilitySyncJob` (D.3 names the job file but no sub-module for M2-03).
   - `apps/server/src/app/feature-modules.ts`: `ImportsModule` in `DOMAIN_MODULES` (the app modules read their feature lists from this file).
   - `apps/server/test/int/authz/evaluator.test.ts`: F.6 rows and operator permission lists for the three new permissions.
   - `apps/server/test/unit/cli/program.test.ts`, `apps/server/test/unit/config/profile.test.ts`: the three new commands and `tenancy.default_region`.
   - `apps/server/test/int/jobs/drivers.test.ts`: 28 pg-boss queues (22 plus the six new jobs).
   - `apps/server/test/int/sso/oidc-admin.test.ts`: the JIT test verified one domain for two organisations, which 0005 forbids; it now removes the domain from organisation B before verifying it for organisation A, and still checks that a domain of another organisation does not count.
2. The guard already read `permissionBy` from the body, path and query, so the guard file is unchanged.
3. `admin.packs.import` already admitted a platform operator without membership in multi tenancy (`pack.install` turns platform-scoped there). `admin.packs.list` did not (403), so its schema now uses `anyOf` with `pack.install` at platform scope. In single tenancy nothing changes.
4. `verified_domain.verified_at` keeps its default `now()`, so the operator command and existing inserts behave as before.
5. `packages/shared/src/pack/datasets.ts` (M2-03 area): `AuditActivityRow.event_type` excludes `internal_audit`, because `ref.audit_activity_template` still has the old CHECK until ref 0002 of M2-03. M2-03 removes the exclusion with its migration.
6. `imports.create` lists `applicability`, `documents` and `risks` and lets the `*` case carry `evidence.manage`, so the guard always has a case (the RBAC sweep needs every case reachable).
7. Behaviour change on purpose (D.2): `auth.providers` answers 429 after 20 calls per minute per address.
8. Behaviour change on purpose (D.2): an Internal Auditor passes the guard of `audit-events.update`, `audit-activities.generate` and `audit-activities.update`. The record check that keeps them to internal audits is M2-05 service work (follow-up 1).

3. M2-S11: `tenant verify-domain` (`verifyTenantDomain` in `src/db/tenant-provisioner.ts`) now fails with the raw unique-violation message when another organisation holds the domain verified; it should answer with a clear message (D.1 `domain_taken`).
4. M2-03: ref 0002 needs `test/int/db/migrate.test.ts` (REF list), `schema-types.test.ts` (table count) and the removal of the exclusion of deviation 5.
5. M2-07: replace `assertKindBuilt` in `registers.service.ts` and remove `pathValues` from `M2-07.json`.
6. M2-08: `imports.commit` has `ms.read` in the guard (J.1); the service must check the permission of the kind again.
7. Every building package deletes its `m2-pending` file when its stubs are gone, and fills its `security/record-tables/M2-*.ts` and `rbac/expectations/M2-*.ts`.
8. `npm run lint` fails at HEAD on `.claude/workflows/mscd-m2-wp.js` (parse error, file not changed here). ESLint should ignore `.claude/**`. Lint of everything else passes.
