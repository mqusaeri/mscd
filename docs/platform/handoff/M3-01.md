# M3-01 handoff: contract, schema, permissions and storage functions

M3-01 writes the whole Milestone 3 contract in wave 1: the 65 new API routes and the 2 new gateway routes of D.1 with schemas, examples and OpenAPI output, the D.2 schema changes on existing routes, D.3 in full (tenant migration 0009, platform migration 0007, Kysely types, enums, permissions, machines, profile keys, modules with stub controllers and stub jobs, schedule entries, the `export` CLI stub), the two storage gateway functions that three later packages call, the disposed-content answer of every open and download path, and `fileGeneratedEvidence`. Every new route answers 501 `not-implemented` after the guard until its building package replaces the stub.

It does not set `replaced_at` (M3-06 owns that change of `file-commands.service.ts`).
8. `erased_person` has `erased_user_id` as its primary key and no `id` column, as D.3 describes.
