# M2-S08 handoff: monitoring and alerts

## What was built

| File | Content |
|---|---|
| `deploy/compose/docker-compose.ops.yml` | The monitoring overlay. Services `ops-init` (one-shot), `prometheus`, `alertmanager`, `node-exporter`, `postgres-exporter`, `blackbox-exporter` and `grafana` (profile `grafana`), each pinned by version and index digest, with a memory limit (768M, 128M, 64M, 64M, 64M, 384M; `ops-init` 128M; about 1.5 GB together with Grafana), `read_only`, `cap_drop: [ALL]`, `no-new-privileges`, `init`, the `local` log driver (20 MB times 10) and no published port. Networks: Prometheus, node-exporter, postgres-exporter and Grafana on `mscd` only; Alertmanager and the blackbox exporter on `mscd` and `egress`. Caddy joins `mscd` (metrics, Grafana) and mounts the `ops_caddy` volume at `/etc/caddy-ops`. Volumes: `prometheus_data`, `alertmanager_data`, `grafana_data`, and the volumes `ops-init` writes: `ops_state` (the `mscd_monitor` password), `ops_prometheus` (probe target), `ops_alertmanager` (configuration and its secret files), `ops_caddy` (Grafana site), one per reader |
| `deploy/ops/ops-init.sh` | POSIX shell, run by `ops-init` as root with only `CHOWN`, `DAC_OVERRIDE` and `FOWNER`, every start, idempotent. Checks every setting first (host names, https addresses, port, email list, Telegram token and chat id together, bcrypt hash, one line, no control characters) and stops with a clear message before writing anything. Then: (1) role `mscd_monitor` (`LOGIN`, member of `pg_monitor`, no other rights, `CONNECTION LIMIT 5`, `default_transaction_read_only = on`, `statement_timeout = 15s`), its random password made once and kept in `ops_state` (owner 65534, 0400), passed to `psql` in the environment and quoted by `format(%L)`; (2) `probe-targets.yml` (file service discovery) from `MSCD_PUBLIC_URL` or `MSCD_OPS_PROBE_URL`; (3) `alertmanager.yml` rendered from the template, with `smtp.password`, the Telegram token and the heartbeat address copied to separate files only Alertmanager reads (owner 65534, 0400); (4) `grafana.caddy` when `OPS_DOMAIN` and `OPS_BASIC_AUTH_HASH` are set, removed otherwise. Never prints the alert address, the heartbeat address or a secret. `--render-only` skips the database and owners (tests) |
| `deploy/ops/prometheus/prometheus.yml` | Scrape every 30 s, rules every 30 s, retention 30 days and 8 GB (the `storage.tsdb.retention` block of Prometheus 3; the flags are deprecated). Jobs `prometheus`, `alertmanager`, `api`, `worker`, `storage-gateway` (port 9464), `node`, `postgres`, `caddy` (`caddy:9180`), `blackbox`, and `public-url` (blackbox probe, module `https_healthz`, targets from `/etc/prometheus/rendered/probe-targets.yml`). The MSCD processes label job runs `job`, which Prometheus moves to `exported_job`; a metric relabelling renames it to `job_name` |
| `deploy/ops/prometheus/rules/*.yml` | 19 alert rules in 8 files, each with `severity`, a plain `summary` and an `action` that names the section of `docs/saas/monitoring.md`: services (TargetDown 2m, PublicUrlDown 2m, DatabaseDown 2m, HttpErrorRateHigh over 2 percent 5xx for 10m, AlertDeliveryFailing), audit and licences (AuditChainBroken, LicenceExpiringSoon under 30 days), jobs (JobFailuresRising 3 in 30m, JobQueueStuck over 900 s, JobOutboxStuck over 0), security (MfaLockSpike 3 in 15m, AccessDeniedSpike over 50 in 10m, `category: security`), host (HostDiskFull over 80 percent, HostMemoryPressure under 10 percent available or memory stall over 20 percent, HostRebootNeeded after 7 days per the M2-S03 follow-up), certificates (CertificateExpiringSoon under 14 days), backups (BackupTooOld over 26 h, BackupMissing for 26 h), Watchdog (always). The api and the worker both publish the collected metrics, so the rules take `max`/`min` per chain, organisation or queue |
| `deploy/ops/prometheus/tests/alerts.test.yml` | Promtool unit tests for every rule (25 test groups): when it must stay quiet, when it fires, the exact labels and text |
| `deploy/ops/alertmanager/alertmanager.yml.tmpl` | The template: global SMTP (`smtp_auth_password_file`, `smtp_require_tls`, `smtp_hello` = domain), routes (Watchdog to `heartbeat` with group interval 30 s and repeat 1 m; critical repeats every 1 h, the rest every 4 h; group by `alertname`), receiver `owner` (email with subject `[MSCD <domain>] Alert: <name>`, and `telegram_configs` with `bot_token_file` when set up), receiver `heartbeat` (`webhook_configs` with `url_file` when set up, otherwise sends nothing). Lines `#@smtp-auth:`, `#@telegram:` and `#@heartbeat:` are kept only when the part is set up |
| `deploy/ops/alertmanager/alertmanager.yml.example` | The template rendered by `ops-init` with the example values (email, login, Telegram, heartbeat). `test-ops.sh` fails when it differs from a fresh render |
| `deploy/ops/alertmanager/templates/mscd.tmpl` | Email (HTML at 16 px with dark-on-light colours of 7:1 contrast or more, and text) and Telegram message (plain text): title, per alert the name, severity, summary, first step and start time in UTC |
| `deploy/ops/blackbox/blackbox.yml` | Module `https_healthz`: GET, only 200, TLS required and verified against the image's public CAs, no redirects, IPv4 |
| `deploy/ops/grafana/**` | Provisioned Prometheus data source (uid `prometheus`), dashboard provider (folder MSCD, no changes from the browser), an empty alerting folder (Grafana sends no alerts), and the dashboard "MSCD overview" (`dashboards/mscd-overview.json`: stat tiles for targets, public address, certificate days, backup age, firing alerts; time series for requests, 5xx share, p95 latency, queue age, job failures, licence days, refused requests, lockouts, processor, memory, disks, database) |
| `deploy/compose/config/caddy/conf.d/ops.caddy` | (1) `http://:9180` with `metrics`, answering only `remote_ip {$MSCD_SUBNET}` (403 otherwise), so Prometheus reads Caddy without the admin endpoint (M2-S02 follow-up); (2) snippet `mscd_ops_grafana <user> <hash>`: `import mscd_tls`, `import mscd_log`, HSTS without `includeSubDomains`, `nosniff`, no `Server`, `basic_auth`, `reverse_proxy grafana:3000` with `X-WEBAUTH-USER {http.auth.user.id}` set by Caddy and `Authorization` removed, and `handle_errors` with the same headers; (3) `import /etc/caddy-ops/*.caddy` (no match without the overlay, which Caddy accepts) |
| `deploy/ops/test-ops.sh` | `--static`: Compose config (also with `grafana`), image pins, only Caddy publishes ports, promtool config and tests, every alert rule has a test, example equals the render, amtool on the full and the email-only render, secrets kept out of the configuration, 12 refused settings that write nothing, Grafana site render, `caddy validate` in acme and internal mode with and without the site, blackbox config check, every dashboard query parses (promtool). Full: `saas-stack.sh up` (M2-S02), the ops overlay with a generated test overlay, the checks listed under "Acceptance", then `saas-stack.sh down`. Settings `MSCD_OPS_TEST_PROJECT`, `MSCD_OPS_TEST_DIR`, `MSCD_OPS_TEST_GRAFANA`, `MSCD_OPS_TEST_KEEP` |
| `docs/saas/monitoring.md` | How it works, what runs and what is scraped, the settings and where they come from, setting up the heartbeat (three checks with period and grace), the uptime check, Telegram, the production test alert (GL-33), every alert with its meaning and first step, silences for maintenance, the optional dashboards, retention of logs and monitoring data for the privacy notice and records of processing, changing an alert, the test, troubleshooting |

## Deviations

| # | Brief | Built | Why |
|---|---|---|---|
| 1 | K.4: `grafana/grafana-oss` | `grafana/grafana:13.2.4` | `grafana/grafana-oss` has had no release since 2 June 2026 (13.0.2, `latest` the same day); the open-source edition is published as `grafana/grafana` (13.1.x, 13.2.x, 13.3.0 since). Using the old name would ship a Grafana four months behind on security fixes. Needs the orchestrator to update K.4 |
| 2 | Alerts of the brief | Also PublicUrlDown, DatabaseDown, AlertDeliveryFailing and BackupMissing | The probe and postgres-exporter scrapes stay `up` when the address or the database is down, so "target down" alone would miss both; a failing mail path and a backup that never ran are silent otherwise. Each has a test |
| 3 | "Grafana ... with basic auth from `ops.caddy`" | The site (TLS, log, headers, basic auth, proxy) is the snippet `mscd_ops_grafana` of `ops.caddy`; `ops-init` writes only the line `ops.<domain> { import mscd_ops_grafana <user> <hash> }` into `/etc/caddy-ops/grafana.caddy` | `conf.d/ops.caddy` is loaded with or without the overlay, so the Grafana host must disappear when it is not set up (a site with an empty address breaks the Caddyfile, and a placeholder name would make Caddy ask Let's Encrypt for it). Grafana itself trusts the user name Caddy sets (auth proxy, Viewer role, viewers may use Explore, no login form, no basic auth, no initial admin, no outbound calls) |
| 4 | Grafana settings | New files `OPS_DOMAIN`, `OPS_BASIC_AUTH_USER` (optional) and `OPS_BASIC_AUTH_HASH` in `/opt/mscd/secrets/ops/`, plus `grafana` in `COMPOSE_PROFILES` | K.2 lists no Grafana item. They follow the same "one file per name" rule as the K.2 monitoring items; the `deploy-prod.yml` and `lib/saas.sh` of M2-S05 in this wave already pass and write these three names |
| 5 | Secrets "from `/opt/mscd/secrets/ops/`" | `ops-init` reads them (with `DAC_OVERRIDE`) and copies the three Alertmanager secrets into the `ops_alertmanager` volume as files of uid 65534, mode 0400; the configuration refers to them with `*_file` | The files belong to the deploying user and `smtp.password` to uid 10001, while Alertmanager runs as `nobody`; changing owners on the host would fight the deploy. The rendered configuration holds no secret |
| 6 | Caddy metrics | Caddy joins `mscd` in the overlay; the metrics site answers only `MSCD_SUBNET` | Prometheus stays on `mscd` only, as the brief asks, so Caddy must be reachable there. Without the global `metrics` option of the Caddyfile (M2-S02 file), Caddy publishes upstream health and process metrics but no per-request counts (follow-up) |
| 7 | `test-ops.sh` acceptance line | Run as `MSCD_OPS_TEST_PROJECT=m2-s08-ops MSCD_OPS_TEST_DIR=/tmp/m2-s08-ops-test MSCD_OPS_TEST_GRAFANA=false MSCD_SAAS_TEST_SCAN=auto MSCD_BUILD_CA=/root/.ccr/ca-bundle.crt` | The prefix rule of this run; the orchestrator decision of M2-S02 for hosts without the Alpine mirrors; and the disk of this host (2 to 4 GB free while other packages built images): the Grafana image takes 2 GB. The Grafana checks of `test-ops.sh` were not run end to end here; the same checks ran in a standalone set-up (below). The default of `MSCD_OPS_TEST_GRAFANA` is `true` |
| 8 | Probe of the public URL | `MSCD_OPS_PROBE_URL` (default `<MSCD_PUBLIC_URL>/healthz`) | The test stack's public address `https://localhost:18443` cannot be reached from a container; production keeps the default |

## Follow-ups

- **M2-S05 (deploy workflow and script):**
  - The names written to `/opt/mscd/secrets/ops/` match (`SAAS_OPS_INPUTS` of `lib/saas.sh`: `ALERT_EMAIL_TO`, `HEARTBEAT_WATCHDOG_URL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `OPS_DOMAIN`, `OPS_BASIC_AUTH_USER`, `OPS_BASIC_AUTH_HASH`), and the folder is created on every deploy, which the overlay needs (`create_host_path: false`). Remaining: a value removed from GitHub (or empty) should remove its file, otherwise an old Telegram token or Grafana host stays in use; and `grafana` must be in `COMPOSE_PROFILES` when `OPS_DOMAIN` is set.
  - The rsync keeps `deploy/ops` next to `deploy/compose`: the overlay mounts `../ops/...`.
  - `saas-deploy.sh` starts the overlay services after the app services. A failure of the monitoring (for example `ops-init` stopping on a missing `ALERT_EMAIL_TO`) should be reported without rolling back a healthy app. Run `ops-init` before Caddy restarts, or restart Caddy after it, so a newly enabled Grafana host is read.
  - Never `down -v`: `prometheus_data` holds the 30 days of metrics and `ops_state` the role password (a lost `ops_state` only makes a new password, which `ops-init` sets).
- **M2-S07 (backups):** write `/opt/mscd/metrics/backup.prom` with the line `mscd_backup_last_success_timestamp_seconds <unix seconds>` (no labels), mode 0644, by writing a temporary file and renaming it. The rules BackupTooOld and BackupMissing and the dashboard read it. After a database restore, run `ops-init` once to recreate `mscd_monitor`.
- **Caddyfile owner (M2-S02 file, orchestrator):** add the global option `metrics` (in the first block of the Caddyfile) for per-request HTTP metrics of Caddy; `conf.d` cannot set global options.
- **M2-S04 documents (orchestrator, or M2-S13 for the checklist columns):** `owner-inputs.md` section 7 can list the optional Grafana items of deviation 4 and the heartbeat check settings of `monitoring.md`; `records-of-processing.md` can mark "Metrics 30 days" as built and add Alertmanager (5 days) and Grafana (user names) from the retention table of `monitoring.md`.
- **M2-S13:** run `deploy/ops/test-ops.sh` in the `saas-smoke` job with `MSCD_OPS_TEST_GRAFANA=true` (GitHub runners have the disk), add `deploy/ops/*.sh` to the shellcheck step, and record GL-17 and GL-32 evidence.
