# M2-17 handoff: terminology

M2-17 applies the two renames the product owner approved for plan question H.1 (product decision 10 of `CLAUDE.md`, 2026-10-28): "Gate" becomes "Checkpoint" and "MS Manager" becomes "Management System Manager". Both apply to the English and the Indonesian screens; the Indonesian screens use the same English words. Every other label proposed in `docs/product/USER-FLOWS.md` keeps its current name.

In plain words: a checkpoint is a phase that must be fully signed off before later phases can start (for the ISMS it is "Risk & SoA"), and a checkpoint item is a record that must be fixed first, such as a control with no linked risk or a Statement of Applicability that is not approved. The Management System Manager is the person who runs one management system day to day, assigns work and verifies what others complete (ISO/IEC 27001 and ISO 9001 clause 5.3).

Only displayed words changed. Code identifiers, API and wire fields (`gates`, `gateItems`, `gate_items`, `holdsGate`, `blockerGateItemRef`), database columns and enum values (`is_gate_item`, `is_gate_phase`), role keys (`ms_manager`), pack keys (`gate.name`, `ms.manager_role`), error codes, message keys (`ms.manager_required`), URL paths (`/ms/{ms}/gates`), test ids, translation keys (`gateItems`, `gateTag`, `noGateItems`) and file names keep "gate" and "manager". The phase "Risk & SoA" keeps its name.

Sentences that used the words were rewritten around them: "an MS Manager" reads "a Management System Manager", "holds the gate" reads "blocks the checkpoint", and the Indonesian "gerbang" in the server messages reads "checkpoint" as well. The job titles of the packs and the people records (ISMS Manager, QMS Manager, BCMS Manager, Anti-Bribery Compliance Function, the `ms.manager_role` labels) stay, and no "followed by the system title" format was added.

### Tera help

The Tera help explains each term in one plain sentence, in English and Indonesian (`apps/web/src/data/static.js`, `TERA`): "A checkpoint is a phase that must be fully signed off before later phases can start, and its checkpoint items are the records to fix first" on Controls & requirements, the same meaning on the Phase board ("..., so a locked phase opens once the checkpoint phase is fully verified"), and "The Management System Manager runs one management system day to day, assigns work and verifies what others complete" as the fourth item of the Portfolio Overview help, next to the role switch.

## Deviations

1. The generic lowercase "management system manager" of Getting started and the Registers read-only note, and the Indonesian "manajer sistem manajemen", now read "Management System Manager" too, so the role has one name on every screen (decision 10 of `CLAUDE.md`). The pack activity "Appoint management system manager" of the generic phases is pack content without an old word and stays.
2. `docs/product/USER-FLOWS.md` described the role label bug that M2-01 fixed. Renaming those sentences alone would have made them wrong, so they now say that each role shows its own label (six statements about the Programme Owner and its row in the label table, five about the Risk Owner, Compliance Investigator and External Auditor, the gap row and the common mistake about role labels).
3. Code comments and JSDoc keep the plan words (MS Manager, gate), as the plans do, and the acceptance `grep` skips comment lines. The developer READMEs next to the server modules (`apps/server/src/modules/*/README.md`) keep them as well.
4. The prototype script of `project/MSCD Mockup.dc.html` reads its label table from `project/mscd-data.js`, which neither the converter nor the export script reads, so that file keeps its words like the other prototypes in `project/`. Opened on its own, the prototype still shows a few table labels such as "Open gate items" and "MS Manager"; the app, its build and every test use `apps/web/src/data/static.js`.
