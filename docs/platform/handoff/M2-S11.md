# M2-S11 handoff: organisation discovery at sign-in

One sign-in page now serves every organisation of the SaaS service. The operator verifies a customer's email domain with a DNS TXT record (only a hash of the token is kept), a worker job checks pending domains hourly for 7 days and verified domains monthly, and sign-in discovery names an organisation only through a verified domain while giving strangers one answer. The sign-in page shows email and password together, adds the matched organisation's company sign-in buttons as the person types, remembers the last organisation, and links the privacy notice and the terms.

## Decisions

1. **`domain.verify` is an hourly cron job outside the daily job ledger.** It works on every organisation at once (installation scope) and runs hourly, so the run ledger of M2-06 (one row per organisation, daily job and local date) does not fit. It follows the cron pattern of `schedules.ts` at minute 35 (between `cleanup.expired` at 20 and the tick at 5), UTC. J.3 names `scheduler.tick` as its trigger; the cron entry does the same job without changing the tick (not owned in this wave).
2. **"Verify now" checks in the request itself**, so the operator sees the result at once (`recordFound`); the job does the first check after add and the hourly and monthly checks.
3. **Audit entries of the checks:** every operator check, every verification, the end of the 7 days and every monthly miss are audited; the hourly misses of a pending domain are not (they would write up to 168 entries per domain) and show as `lastCheckedAt`.
4. **A domain verified by hand in multi tenancy is audited `ops.domain_verified`** with `method: 'manual'`, the reason and `via: 'cli'`, like every other domain event of the SaaS track; single tenancy keeps `tenant.domain_verified` and its output, which the Milestone 1 tests check.
5. **The remembered organisation is the organisation of the session** (`me.org.slug`) whenever the application opens. The `?org=` of a link is never stored, so a link sent to the wrong person does not change what the browser remembers.
6. **The email lookup also runs when an organisation is preselected**, and an answer with sign-in buttons takes over, so a person on a shared computer or with a link of another organisation still finds theirs. An answer without buttons never hides the preselected organisation's buttons.
7. **D-S10 and the local sign-in policy:** without sign-in buttons the answer never reveals an organisation's policy (`local` is the installation's), so a known organisation that disables local sign-in and has no provider looks like an unknown one. The sign-in itself still applies the policy (F.4).
8. **Archived organisations:** add and "Verify now" answer 409 `organization_archived`; list and remove still work; the sweep skips their domains.
9. **A link to an organisation that allows SSO only offers "Use a different organisation".** By D-S10 an email of an organisation without SSO gets the stranger's answer, which never replaces the link's answer, so without the switch such a person could not reach the password field without editing the address. The switch shows only while the link's answer hides the password; it drops the preselection of the page and leaves the remembered organisation in place (decision 5).

## Deviations

1. **Message keys** beyond J.6, all on existing slugs: `domain_already_verified`, `domain_not_dns`, `domain_changed`, `organization_archived` (409 `conflict`). J.6 lists `domain_taken` and `domain_not_allowed`, which are used as written.
2. **`ops.domains.verify` answers `OrgDomainCheck`** (an `OrgDomain` with `recordFound`), and `OrgDomain` gained `pendingUntil`: schema changes in the area file this package owns (R-14).
3. **A typed whole address** (`rina@ndt.co.id`) is accepted by `add` and `verify-domain` as its domain.
4. **The API E2E stack does not start the DNS responder.** `apps/web/e2e-api/stack.mjs` is not owned here, and its stack runs single tenancy, where the domain routes answer 409. The responder is ready for it (`--dns-port`, `startMockProviders({dnsPort})`); see follow-up 2.
