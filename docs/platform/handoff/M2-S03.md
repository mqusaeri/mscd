# M2-S03 handoff: server bootstrap

## What was built

| Area | Files | Content |
|---|---|---|
| Bootstrap script | `deploy/scripts/bootstrap-host.sh` | Prepares a fresh Ubuntu 24.04 LTS server as root, in nine steps: data volume, system packages, Docker Engine, time, swap and journal, accounts, folders, security updates, firewall, SSH. Each step compares the server with the target state first and reports `done`, `changed` or `skipped`, so a second run changes nothing. Modes: a real run, `--render-only --root DIR` (every configuration file under DIR, nothing else), `--dry-run` (prints each command), `--check` (lists every difference, exit 1 when there is one). Options of the plan: `--admin-user`, `--deploy-key-file`, `--data-device`, `--format-data-device`; added: `--admin-key-file`, `--ssh-host`, `--skip-upgrade`, `--only` (deviation 3). Output: host key fingerprints and the lines for `DEPLOY_SSH_KNOWN_HOSTS`, also saved in `/opt/mscd/state/ssh-known-hosts`. Log of each real run: `/var/log/mscd-bootstrap.log` (0600) |
| SSH | `deploy/host/ssh/10-mscd.conf` | `/etc/ssh/sshd_config.d/10-mscd.conf`: `PasswordAuthentication no`, `KbdInteractiveAuthentication no`, `PermitRootLogin no`, `AuthenticationMethods publickey`, `MaxAuthTries 4`, no X11, agent or TCP forwarding, no tunnels, `AllowUsers deploy <admin>`. The file is first in `sshd_config.d`, so its values win; the script also checks the values in effect with `sshd -T` and stops when another file overrides them |
| Docker | `deploy/host/docker/{daemon.json,docker.sources,docker.asc,data-volume.conf,var-lib-docker.mount}` | `daemon.json`: `live-restore: true`, `log-driver: local` (20 MB, 5 files), `default-address-pools` 172.16.0.0/13, 172.24.0.0/14, 172.28.0.0/15 and 172.30.0.0/16 (size 24), which cover 172.16.0.0/12 except 172.31.0.0/16, the range of the fixed `mscd` subnet 172.31.250.0/24 and the `edge` subnet of M2-S02. Docker CE, CLI, containerd, Buildx and the Compose plugin from `download.docker.com` (deb822 source for `noble`); Docker's signing key is stored in the repository and checked by SHA-256 before use (fingerprint `9DC8 5822 9FC7 DD38 854A E2D8 8D81 803C 0EBF CD88`). Conflicting packages (`docker.io`, `podman-docker`, `containerd`, `runc` and others) are removed first. `daemon.json` is written before Docker is installed and checked with `dockerd --validate`; Docker restarts only when it changed while Docker was running |
| Data volume | same folder | `--data-device` mounts the volume at `/var/lib/docker` with the systemd unit `var-lib-docker.mount` (by file system UUID, `nofail`), and the drop-in `docker.service.d/10-mscd-data.conf` (`RequiresMountsFor=/var/lib/docker`) keeps Docker stopped when the volume is missing. `--format-data-device` formats ext4 (`-L mscd-docker -m 1`) only when the device has no partition, no signature (`wipefs`) and only zeros in its first megabyte. An existing ext4 or XFS file system is kept. The script refuses to mount over a non-empty `/var/lib/docker` or while Docker runs |
| Firewall | `deploy/host/firewall/{ufw-rules,fail2ban-sshd.local}` | ufw: IPv6 on, deny incoming, allow outgoing, `limit 22/tcp`, `allow 80/tcp`, `allow 443/tcp`, `allow 443/udp` (each with a `mscd-*` comment), enabled at boot. Other rules stay and are listed as a warning. fail2ban jail `sshd` in `/etc/fail2ban/jail.d/mscd.local` (read after the `.conf` defaults): systemd backend, aggressive mode, 5 failures in 10 minutes, ban 1 hour growing to one week |
| System | `deploy/host/system/{journald.conf,sysctl.conf,swapfile.swap,unattended-upgrades.conf,mscd-reboot-marker,mscd-reboot-marker.service,mscd-reboot-marker.timer,sudoers-admin}` | UTC with chrony; 4 GB `/swapfile` as the systemd unit `swapfile.swap` with `vm.swappiness = 10` (an existing smaller swap file is reported by `--check` and replaced by a real run: `swapoff`, new file, `mkswap`); journald `Storage=persistent`, `SystemMaxUse=1G`; unattended-upgrades for the Ubuntu security origins every day, no automatic reboot (`/etc/apt/apt.conf.d/52mscd-unattended-upgrades`); the reboot-needed marker (see Monitoring below); sudo without a password for the admin account (`/etc/sudoers.d/90-mscd-admin`, checked with `visudo -c`) |
| Accounts | in the script | `mscd` system account (same `useradd` flags as `lib/common.sh`); `deploy` with a locked password, in `docker`, never in `sudo`, its `authorized_keys` fully managed with `restrict` before each key; the admin account in `sudo`, its keys from `--admin-key-file` added (other keys kept), or root's keys copied without their options when no file is given. A key line commented out with `#` never counts as a key, for this check and for the lockout guard of the SSH step. A real run refuses the test key of `deploy/host/test` |
| Folders | in the script | `/opt/mscd` 0755, `releases` 0755, `state` 0750, `logs` 0750, `secrets` 0700, `backup` 0700, `metrics` 0755, all owned by `deploy` |
| Workflow | `.github/workflows/bootstrap-prod.yml` | `workflow_dispatch` only; inputs `target` (`staging` or `production`), `admin_user`, `admin_public_key`, `deploy_public_key`, `host_key_fingerprint`, `data_device`, `format_data_device`; environment `${{ inputs.target }}`; job concurrency `deploy-<target>` with `cancel-in-progress: false`; top-level `permissions: contents: read`; secrets and inputs reach scripts only through `env`. Steps: check the inputs (three different keys, valid fingerprint and names), `ssh-keyscan` and compare with the fingerprint (stop before any login on a difference), one SSH connection as root (ControlMaster) with the pinned key, copy the script and `deploy/host/{ssh,docker,firewall,system}` with the two public keys to `/root/mscd-bootstrap`, run the script, read `/opt/mscd/state/ssh-known-hosts` over the same connection (root logins are off by then) and check that it holds the pinned key, write the job summary, close the connection and delete the key |
| Tests | `deploy/host/test/{ubuntu-image,deploy.pub,bootstrap-test.sh,workflow-test.sh}` | See Tests |
| Guide | `docs/saas/bootstrap.md` | Provider steps, block volume, keys, GitHub secrets, DNS records (A, AAAA, CAA, optional `ops`), the workflow run and what to do after it, data volume, ports and why Docker-published ports bypass ufw (only Caddy publishes), fail2ban, accounts, sudo password option, updates and reboots, folders, running the script again with `--check`, `--dry-run`, `--only`, replacing the deploy key, closing port 22 later with the Tailscale GitHub Action |

### Monitoring marker (for M2-S08)

`mscd-reboot-marker.timer` runs `/usr/local/lib/mscd/reboot-marker` 2 minutes after boot and every 15 minutes. It writes `/opt/mscd/metrics/reboot.prom` (0644, atomic rename) for the node exporter's textfile collector:

| Metric | Meaning |
|---|---|
| `mscd_host_reboot_required` | 1 when `/run/reboot-required` exists, else 0 |
| `mscd_host_reboot_required_since_timestamp_seconds` | modification time of `/run/reboot-required`, 0 when no reboot is needed |

## Fixes after review

| # | Finding | Fix | Proof |
|---|---|---|---|
| 1 | The SSH rate limit was described as "more than 6" connections | `deploy/host/firewall/ufw-rules`, `docs/saas/bootstrap.md` and the M2-S05 follow-up now say that ufw refuses the 6th new SSH connection from one address within 30 seconds, so at most 5 are allowed | The reviewer's test in a container (connections 1 to 5 accepted, 6 to 8 refused) and the ufw manual ("6 or more connections in the last 30 seconds") |
| 2 | `has_key_lines` counted a commented key line as a key, so the admin key check and the lockout guard could pass with no working key | Lines that start with `#` (after optional spaces) are skipped before the key pattern is matched | Two new checks in `bootstrap-test.sh`: with only `# ssh-ed25519 ...` in the admin's `authorized_keys`, the accounts step stops ("root has none to copy") and the SSH step stops at the lockout guard ("The account owner has no SSH key") |
| 3 | The size of an existing `/swapfile` was never checked | `swap_ok` compares the file size with 4096 MB first, so `--check` reports "/swapfile is N MB, smaller than 4096 MB". A real run turns the old file off (`swapoff`), removes it and writes a new 4 GB file with `mkswap`; the free space check counts the space the old file frees. A larger file is kept | Two new checks in `bootstrap-test.sh` with a 64 MB swap file: `--check` exits 1 with the size line, and the dry run prints `rm -f /swapfile`, the 4096 MB `dd` and `mkswap /swapfile` |
| 4 | The "bootstrap-prod.yml parses" check loaded `yaml` from the current folder and failed outside the repository root | `yaml` is resolved with `require.resolve('yaml', { paths: [REPO_DIR] })`, as in `workflow-test.sh` | `bootstrap-test.sh` passes when started from `/tmp` |
| 5 | shellcheck reported SC1091 twice for `/etc/os-release` (exit 1), against the claim of this note | `/etc/os-release` is read once in one subshell that prints the three values, so the one directive covers it | shellcheck 0.9.0 exits 0 for `bootstrap-host.sh` and the marker |
| 6 | `npm run lint` failed on `.claude/workflows/mscd-m2-wp.js` | No change in this package (the file is owned by no package). The orchestrator added `.claude/` to the ESLint ignores in commit 76575e9 | `npm run lint` passes |

## Follow-ups

| For | Item |
|---|---|
| M2-S05 | ufw allows at most 5 new SSH connections from one address within 30 seconds and refuses the 6th. `deploy-prod.yml` must keep one SSH connection open for all its commands (ControlMaster, as `bootstrap-prod.yml` does) or send the secret files of `/opt/mscd/secrets/{backup,ops}` in one connection; otherwise connections are dropped |
| M2-S05 | The deploy key has `restrict`: never use `ssh -t`. `DEPLOY_SSH_KNOWN_HOSTS` holds hashed lines for port 22; when `DEPLOY_SSH_PORT` changes, the lines must be made for `[host]:port`. Use the concurrency group `deploy-${{ inputs.target }}` as planned, which `bootstrap-prod.yml` shares |
| M2-S05 | `/opt/mscd` and its folders belong to `deploy`; `/opt/mscd/state/ssh-known-hosts` belongs to root (0644) and must stay. `curl` and `rsync` are installed on the host |
| M2-S02 | IPv6 clients: Docker's userland proxy forwards IPv6 connections to an IPv4-only container with the gateway address as the source, so Caddy and NGINX see one address for every IPv6 user (rate limits per address, access logs). Give the `edge` network `enable_ipv6: true` with an IPv6 subnet, or publish only the A record until then. The `edge` subnet must stay inside 172.31.0.0/16, which the Docker address pools leave free |
| M2-S08 | Alert on `mscd_host_reboot_required == 1` (for example after 7 days with `time() - mscd_host_reboot_required_since_timestamp_seconds > 7 * 86400`), read from `/opt/mscd/metrics/reboot.prom` |
| M2-S07 | The bootstrap copies only `deploy/host/{ssh,docker,firewall,system}`; the units of M2-S07 in `deploy/host/systemd/` are installed by M2-S07's own steps. `/opt/mscd/backup` is 0700 and owned by `deploy` |
| M2-S04 | `owner-inputs.md` and the checklist can name the three keys (bootstrap, admin, deploy), the workflow inputs of deviation 2, the secrets `BOOTSTRAP_SSH_KEY` and `DEPLOY_HOST` before the run, and the deletion of `BOOTSTRAP_SSH_KEY` after it. `docs/saas/README.md` can link `bootstrap.md` |
| Owner | No server was touched (rule S-1). The steps that need systemd and a real disk (data volume, packages, Docker, time, swap, journal, updates, fail2ban) were proven by the dry run and the code checks only. The first staging run is their first real run: afterwards run the script with `--check` on the server and keep its output with the go-live evidence |
