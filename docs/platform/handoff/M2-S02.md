### `saas-stack.sh`

- **up:** removes what an earlier run of the same project left, checks that the two ports are free, picks the networks (`172.31.250.0/24` and `172.31.251.0/24`, or the first two free `172.31.x.0/24` ranges when another Docker network uses them), makes a throwaway key set with `saas-keys.sh --print-only`, builds the release images with it (`build-release-images.sh --load --registry localhost/<project>`), copies the build logs into the state folder, writes `.env` from `.env.saas.example` (`MSCD_TLS_MODE=internal`, `MSCD_DOMAIN=localhost`, `MSCD_PUBLIC_URL=https://localhost:18443`, the digests of `digests.json`, Mailpit as SMTP relay, the site on `site.localhost`, `MSCD_EDGE_IPV6=false` when the host has no IPv6), fills the secrets folder (the production `platform.key`, `storage.key` and audit anchor pair of the key set, the rest with the generators of `lib/common.sh`), copies `index.html`, `id/` and `assets/` of `apps/site`, writes a test overlay (Caddy on `127.0.0.1:18080` and `127.0.0.1:18443`, Mailpit on the internal network without a port), runs `docker compose config -q` and `up -d --wait` (migrate first, its exit code checked) and copies `/data/caddy/pki/authorities/local/root.crt` to `/tmp/mscd-saas-test/caddy-root.crt`. State folder `MSCD_SAAS_TEST_DIR` (default `/tmp/mscd-saas-test`, must be under `/tmp` or `$TMPDIR`).
- **check:** the five assertions of the brief plus the two of the acceptance text and a few more:
  - tenancy mode `multi`, read by the configuration loader of the server inside the `cli` service (`docker compose run --rm cli`), and the flavour `release`;
  - only Caddy publishes ports (from `docker inspect` of every container of the project), and it publishes 80/tcp, 443/tcp and 443/udp;
  - `curl --cacert /tmp/mscd-saas-test/caddy-root.crt https://localhost:18443/healthz` answers 200; `http://localhost:18080/` answers 308 to `https://localhost/`; HSTS is exactly `max-age=31536000; includeSubDomains`; the app page has the Content-Security-Policy with `frame-ancestors 'none'`, `X-Frame-Options: DENY`, no `Server` header and no `fonts.googleapis.com` (GL-25, GL-56);
  - 80 requests at once to `/api/v1/auth/mscd-rate-limit-probe` get at least one `429` with `Retry-After: 1` and `application/problem+json` and nothing but 404 and 429; three seconds later the address is served again;
  - a request with a forged `X-Forwarded-For: 203.0.113.99`: NGINX logs the address Caddy saw, neither the forged one nor Caddy's; a `token` query value reaches neither the Caddy nor the NGINX log; Caddy writes a JSON line with the query string removed;
  - `GET /api/v1/system/profile` through Caddy reports `deploy` `saas`; the site on `site.localhost` answers 200 with its own CSP and HSTS without `includeSubDomains`, and `check.mjs` answers 404;
  - audit anchor: `cli tenant create` adds a row to the platform audit chain, the job `audit.verify-chain` is queued through pg-boss inside the worker container, the script waits for "audit.verify-chain done", then asserts that the worker log has no line "not among the anchor keys compiled into this build" and that the worker wrote an `audit.anchor` line (so the key was really used).
- **down:** `docker compose down --volumes --remove-orphans` (cli profile included), then removes any container, volume or network still labelled with the project, the two test images (unless `MSCD_SAAS_TEST_KEEP_IMAGES=true`) and the state folder.

## Deviations

| # | Brief | Built | Why |
|---|---|---|---|
| 1 | `reverse_proxy web:8080` | `reverse_proxy {$MSCD_WEB_UPSTREAM:web:8080}`; Compose sets `MSCD_WEB_UPSTREAM=tcp4/<MSCD_WEB_EDGE_ADDRESS>:8080`, the web container's fixed IPv4 address on `edge` | With IPv6 on the edge network (deviation 4) the name `web` also resolves to an IPv6 address. Caddy would then reach NGINX from its IPv6 address, which `MSCD_TRUSTED_PROXY_CIDRS=<caddy address>/32` does not cover, and every client would share Caddy's address in the logs and the limits. The fixed IPv4 address keeps the one trusted hop. Without the variable the Caddyfile still uses `web:8080` |
| 2 | Rate limits in `40-mscd-runtime.sh`, `MSCD_RATE_LIMITS=false` turns them off, on-premise defaults unchanged | The image default is `MSCD_RATE_LIMITS=false`; the SaaS overlay sets `true`. The limits apply under `/api/` only (the static app files are not limited) | "On-premise defaults stay unchanged": `docker-compose.yml` and the Helm chart have no owner in this wave, so the only way to keep their behaviour is an image default of off. The 429 answers carry the problem headers of the api, which belong to `/api/` |
| 3 | Caddy ports 80/tcp, 443/tcp, 443/udp | Published without a host address; the test overlay of `saas-stack.sh` publishes them on `127.0.0.1` | Compose cannot leave the host address empty through a variable, and `0.0.0.0` would publish on IPv4 only |
| 4 | Fixed-subnet `edge` network | Plus `enable_ipv6: ${MSCD_EDGE_IPV6:-false}` and `MSCD_EDGE_SUBNET6`; the example settings say `true` | M2-S03 follow-up: with an `AAAA` record and an IPv4-only edge network, Docker's userland proxy forwards every IPv6 client from one gateway address, so all IPv6 users would share one rate limit. Docker ignores the IPv6 subnet when the flag is false (tested here). The IPv6 path itself could not be tested on this build host, whose kernel has no IPv6 (follow-up) |
| 5 | `saas-stack.sh up` builds with `build-release-images.sh` | Default unchanged (`MSCD_SAAS_TEST_SCAN=gate`). `MSCD_SAAS_TEST_SCAN=auto` builds the same images through `build-bundle.sh --images-only --os-updates auto --scan auto --pull --attest`, writes `digests.json` itself and checks the release label; the scan stays a gate when the Alpine updates were applied and only reports when they could not be | On this host the Alpine mirrors are blocked, so the web image keeps `brotli-libs` 1.2.0-r1 and `curl` 8.22.0-r0 of its base and the gate refuses it (the known M2-S01 finding, orchestrator decision "re-run on a host that reaches dl-cdn.alpinelinux.org"). The server image passes the gate here |
| 6 | Project `mscd-saas-test` | Default `mscd-saas-test` (`MSCD_SAAS_TEST_PROJECT`); every run here used `MSCD_SAAS_TEST_PROJECT=m2-s02-saas` | The concurrency rules of this run ask for the `m2-s02-` prefix on every container, network, volume and project |
| 7 | Mailpit "added" by `up` | A generated test overlay `<state>/compose.test.yml`, deleted by `down` | No test Compose file is in the Owns list, and the overlay must not ship to a server |
| 8 | Tenancy mode "through the cli service"; "after running the audit anchor job" | The configuration loader of the server run inside the `cli` service; the job queued through pg-boss in the worker container, after `cli tenant create` | No CLI command prints the tenancy mode or runs a job (`diagnostics` is an M2-S09 stub). The job loads the anchor key only when a chain has a new head, so a new organisation is created first; the check also requires the `audit.anchor` line, so it cannot pass without using the key |
| 9 | (extra of MOT-01) | The marketing site of `apps/site` on `MSCD_SITE_DOMAIN`, as in the sketch of `docs/site.md`, with HSTS without `includeSubDomains` and frame blocking added | `includeSubDomains` on the bare domain would force HTTPS on every name of the owner's domain (mail, intranet). The site is off while `MSCD_SITE_DOMAIN` is empty |
