# M2-04 handoff: pack content

M2-04 writes the content step of the six framework packs (MILESTONE-2 E.2): clauses 4 to 10 with their sub-clauses, clause 10 numbered as each standard numbers it, documented information, document templates, management review inputs, Annex A control-to-clause links and evidence examples, an evidence example for every leaf clause row, corrected flags, cycle derivations, ISO 37001 chain fixes, prep tasks without demo facts, and the minor version step of E.3. The sample (`mscd-data.js`) moves with the packs where the demo shows the same content, and the seed snapshot is regenerated from it.

Every pack also has:

- `documented_info_mandatory` true on the rows that `documented_info.csv` names and on their parents; an evidence example on every leaf row (`clauseEvidenceMissing` 0 everywhere).
- Document templates covering every activity output code of the pack (strict references hold in every pack), plus the scope statement: `SCO-01` linked to 4.3 in ISO/IEC 27001, `SCO-Q01`, `SCO-B01` (4.3.2) and `SCO-A01` in the other packs (H.9). Template codes are unique per pack; each system has its own policy code (`POL-01`, `QM-01`, `POL-B01`, `POL-A01`); the information security risk assessment method is `PRC-04`, because the demo's `PRC-05` is the asset handling procedure (the code clash of the gap study). - Prep tasks without demo facts (`NC-2025-02`, `SoA v3.0`, `SharePoint`, `DC Jakarta`, "Internal audit 2026 report", `EX-01`, "(14)"); codes, days and the first-audit flag kept. ISO 37001 gets five prep tasks of its own; ISO 9001:2026 gets general ones in place of the transition tasks, and general cycle items ("Internal audit covering all requirements", "Management review with all mandatory inputs", no `EDITION_TRANSITION`). The ISO 9001:2015 pack keeps the demo's cycle titles, because the demo QMS is certified on that edition and the seed links its cycle items to the definitions by title.
- ISO 37001 chain: auditor questions in English and Indonesian for all six stages, `clause_at_risk` per stage (context 4.1, bribery risk 4.5, control 8.1, associate 8.2, document 7.5, evidence 8.1 / 9.1).
- Activities: the completion source of the objectives activity (3.4 in ISO/IEC 27001, 3.3 elsewhere: the objectives register), of role-based training (7.2: the competence register) and of 4.9 Approve risk treatment plan (its output document `PLN-01`) in `expected_outcome`.

## Deviations

1. **Clause trees written for this package.** The "packs research" that E.2 cites is not in the repository, so the trees, short titles, documented information, templates, review inputs and evidence examples were written from the published structure of each standard to the counts of E.2. Two counting choices: ISO 9001 and ISO 22301 count the numbered paragraphs of 7.5.3 (7.5.3.1, 7.5.3.2) as rows; ISO 22301 keeps 8.4.4 Business continuity plans as one row (its numbered paragraphs 8.4.4.1 to 8.4.4.3 are not rows). The scope statement template is inside each template count, so no count of E.2 was raised. Every pack waits for the lead auditor sign-off table of `packs/README.md`.
2. **The sample keeps the Milestone 1 pack card versions.** `extract-from-sample.mjs` checks the sample's `PACKS` versions against its own pack table (`PACK_DEFS`), which is in `packs/scripts` (not in this package's paths). The released version is in `packs/content/<pack_id>/manifest.json` (M2-03 deviation 2). So the parity test no longer adds one patch step: it maps each card version to the released version of its pack, read from `packs/sources`. Sample mode shows 1.2.0 and the API 1.3.0 for ISO/IEC 27001.
3. **The ABMS update offer.** The sample's ABMS card offers "0.7.0: 26 more activities, 80 finding conditions", and the seed writes it to `platform.pack_catalog`. 0.7.0 is now the installed content step, so the API offers no update for ISO 37001:2025. The sample keeps the offer (its card still shows 0.6.0); parity asserts the API side.
4. **Annex A examples live in the pack content; the sample keeps its ten.** As the brief says, the 83 new Annex A examples and the clause examples are in `packs/content`. The sample keeps its ten examples, so the API's `EXAMPLES` holds more entries than the sample's. Parity checks every sample example unchanged and every API key against the pack row of that key in the organisation's systems. The loader of M2-07 keys the clause rows of a catalogue edition `cl-<code>`, so no ISMS clause example replaces an Annex A example. The clause rows of ISO 9001, ISO 22301 and ISO 37001 keep the bare clause code, and `EXAMPLES` is one map per organisation in which the first system wins. So where two systems give the same key, the later system's clause row shows another row's example: in ndt, 20 Annex A keys (5.1 to 8.10) hide the QMS, BCMS and ABMS clause rows of the same number (QMS 7.2 Competence shows the example of Annex A 7.2 Physical entry), and 36 clause keys of those three standards hide each other (BCMS and ABMS 4.1 show the QMS example); in bsd, 7 Annex A keys (5.3, 6.3, 7.2, 7.3, 7.4, 8.1, 8.6); none in rmn. Parity asserted these counts. Fixed in the orchestrator follow-up run (section below): `EXAMPLES` is keyed by system and row (`qms:7.2`, `isms:7.2`), and `EXAMPLE_COLLISIONS` is gone.
5. **ISO 37001 questions only in the packs.** The sample's ABMS stages keep empty questions, because a question in the sample needs its Indonesian text in `QUESTION_ID` of `extract-from-sample.mjs` (not in this package's paths). The API shows the pack questions on the ABMS stages and chain items; parity asserts them.
6. **Completion source as text.** The pack format has no completion source column (R-14 allows no new format value), so the objectives, training and risk treatment plan activities state their source in `expected_outcome`; 4.9 also names its output document `PLN-01`.
7. **Demo prep task titles.** The demo keeps its prep task wording (E.4: "the sample keeps its own wording where the demo needs it"; Milestone 1 tests outside this package name "Approve SoA v3.0" and "Close NC-2025-02 ..."). The seed links prep tasks to templates by title, so the demo's ISMS, QMS and BCMS tasks would lose their template link; a one-line fallback in the seed (template at the same position, `PREP-nn`) is in the patch below.
8. **Phase 9 is dropped from ISO 9001:2026 only.** The demo QMS runs on ISO 9001:2015 with the transition phase on its phase board, and the seed copies its activities from the 2015 pack, so the 2015 pack keeps the phase "ISO 9001:2026 transition" (14 activities, with "Complete the edition transition gap tasks" in place of "(14)"). For a customer on ISO 9001:2015 the phase is the plan for the move to the new edition, so it is release content of that pack. Renaming it would change the sample and five Milestone 1 specs outside this package (`phases`, `timeline`, `switching`, `portfolio`, `framework`). The same holds for the cycle items of the 2015 pack ("Internal audit against 2026 edition", "Management review incl. transition", "Edition transition tasks complete"): the demo seed links its QMS cycle items to them by title. The ISO 9001:2026 pack has general cycle items and no transition phase. M2-18 must know this for its release check (follow-up).
9. **Review inputs are mandatory.** Every input of clause 9.3 of the standards is required, so all pack inputs are mandatory. A management review now needs every input before it closes (BR-13): ten for an ISMS, twelve for a QMS. `management-reviews.test.ts` (Milestone 1, no owner in this wave) gets the new expected values in the patch below.
