# M2-S12 handoff: operator console, organisations, status, domains and entitlements

The operator console now runs the whole life of a customer organisation in the browser. The organisations list shows each organisation's status, plan, users against the limit, last day of the plan with the days left, licence state and verified domains, with a status filter and a search. "Create organisation" takes a plan preset. "Manage" opens a drawer with five tabs: Overview, Status (the moves of J.8), Domains (DNS TXT verification), Entitlements (preset or custom limits with `If-Match`) and History. Only `apps/web/src/screens/ops/**` and this package's test and spec files changed. No server code, shared contract, generated view or shared web file changed.

## What was built

### Organisations list (`ops/Organizations.tsx`)

| Part | Content |
|---|---|
| Columns | Organisation (name and slug), Status (badge: Active, Suspended, Offboarding, Archived), Plan (the plan name; "No plan" without an entitlement), Users ("41 of 50" with a bar; the members alone when the limit is unknown), Valid until (the date, "No end date", and a days-left badge: grey, amber from 30 days, red once ended), Licence (state badge), Verified domains (wrapped only after their dots), Actions ("Manage", and "Install licence" as before). M2-16's Members, Management systems and Created columns are gone (deviation 5) |
| Filters | Search by slug or name (300 ms pause, as before) and a Status select (all, or one status) sent as `status` of `ops.organizations.list`; an empty result says "No organisation matches the search." or "No organisation has this status." |
| Users column | `OpsOrganizationItem` has no user limit, so the API adapter reads `ops.organizations.get` for each row of the page, at most 4 at a time (`DETAIL_READS`); a failed read leaves the limit unknown (deviation 1) |
| Drawer | "Manage" opens `OrgDrawer` for the organisation; every change in the drawer reads the list again, so the row shows the new status, plan and domains |
| Create organisation | A "Plan" select with the presets of `ops.plans.list` ("trial: users 10, systems 1, days 30") and "No plan yet: set the limits later in Entitlements". The first preset is the default until the operator picks another (the smallest preset when `license.plans` keeps its D-S4 order). The body carries `preset` only when one is chosen. The result shows the server's message, which names the plan. The one-time link still shows only when the answer carries `invitationUrl`, which never happens on SaaS (`mail.required`). A failed read of the presets says so in the field hint and leaves "No plan yet" |
| Single tenancy | Unchanged: 409 `single_tenancy` shows that one organisation runs here; no filter, no Manage |

### Organisation drawer (`ops/OrgDrawer.tsx`, `StatusTab.tsx`, `DomainsTab.tsx`, `EntitlementsTab.tsx`)

The drawer (560 px, the kit's `Drawer`) shows the slug and the status badge above five tabs. The last detail stays on screen while it is read again after a change.

| Tab | Content |
|---|---|
| Overview | The `ops.organizations.get` fields: slug, status, region, created, members, management systems, plan and the source of the limits (plan preset, set by the operator, signed licence file), users and systems against their limits, valid until with the days left, every email domain with its status, last sign-in ("Nobody has signed in yet"). Without an entitlement: "No plan yet: no users or systems can be added." |
| Status | The current status with one plain sentence on what members can do. The allowed moves of J.8 as buttons: "Suspend", "Reactivate", "Start offboarding", "Archive" (archived: "Archived is final. No move is possible."). Each opens a dialog that lists the effects first (sessions, data, jobs and emails, the 30-day read-only period of D-S5, the email to the Tenant Admins, and "set the new plan in Entitlements" when reactivating from offboarding), then asks for a reason (3 to 500 characters) and, for "Start offboarding" and "Archive", the slug typed again. The console checks both before sending and sends what was typed as `confirmSlug`; the server checks it again. The answer shows "Sessions ended: n." and "Tenant Admins emailed: x of y." (amber, with a note to tell them yourself, when fewer went out). 409 `invalid_status_transition` and 422 `confirmation_mismatch` show the server's message in the dialog. In offboarding the tab reads the history and says when the read-only period ends, or that it ended and the organisation should be archived now (the operator archives by hand, M2-S09 follow-up 8) |
| Domains | Each domain as a block (the drawer is too narrow for a five-column table): name, state badge (Pending, Verified, Failed), method (DNS record, By the operator command), "Checked every hour until ..." for a pending one, "Verified ...", "Last check ..." or "Not checked yet", and "Not found within 7 days. Add the domain again for a new value." for a failed one. "Add domain" opens a dialog: the domain (a typed address works, the server normalises it), then the TXT record: type, name and value, each with "Copy", and the warning that the value is shown only once. Closing the dialog drops the value from the page (GL-50). "Verify now" (DNS domains only) shows whether the record was found: verified now, still in place, not found yet (with the end of the hourly checks), the 7 days ended, or the record gone while the domain stays verified; 503 says DNS did not answer and nothing changed. "Remove" asks first and names what changes for the organisation's people. An archived organisation shows no "Add domain" or "Verify now" (the server refuses both) |
| Entitlements | The current entitlement: plan, source, users and systems against their limits, valid from and until with the days left, grace days, rate limits ("Default" when empty), standards ("Every installed standard" when none), evidence storage, features, version and time of the last change. Without one: "No plan yet" with what that means. The change form: "Plan preset" (custom limits or a preset); a preset shows its limits and its last day for the chosen first day; custom limits take the plan name, users, management systems, valid from, valid until or "No end date", grace days, both rate limits, standards, evidence storage and features. The form opens with the current row as custom limits. A preset picked in place of custom limits starts today, so a renewal (for example after a reactivation from offboarding) does not take the first day of the plan that ends; a move from one preset to another keeps the day shown, and a move back to custom limits shows the row's first day again (`planPicked`). An organisation without an entitlement starts on the first preset, today. Save sends `If-Match` (the ETag of the read, `*` without a row). 412 shows the conflict and loads the latest values into the form. The warnings of the answer (a limit below the current use, LIC-USERS and LIC-MS) show in both languages above the summary |
| History | `ops.organizations.events`, 20 per page, newest first: when, the move (two status badges), the reason, and who ("Operator command" for a move without a user) |

Rights: the moves and the domain actions need `ops.tenants.manage`, the entitlement form `ops.entitlements.manage` (as the routes); without them the tab says what the operator can do and shows no action.

## Decisions

1. **The sample service has five organisations:** the three of the snapshot and two of the sample service only, so the sample build and its specs show every status but archived (reached by the spec's own moves) and every tab with data. The sample state belongs to the installation, because the operator sees every organisation; it is not kept per organisation of the snapshot.
2. **The first preset is the default plan of "Create organisation"**, with "No plan yet" as an explicit choice.
3. **The slug confirmation is checked in the console and by the server.** The console sends what was typed; the API spec shows the server's 422 text when the two differ.
4. **The end of the read-only period** is the start of the newest move to offboarding plus 30 days (D-S5), shown in the Status tab of an organisation in offboarding.
5. **SMB, S3 and WebDAV are not offered** in the custom limits (plan B: not built). A row that holds one keeps it ticked, and so do framework codes outside the four packs.
6. **Refusals:** the server's `messages` are shown as they are. Where an answer has none (412, 503, `organization_archived`, `domain_changed`), the console has its own text in both languages.

## Deviations

1. **The users column reads the detail of each row.** `OpsOrganizationItem` has no user limit and the contract is not owned here (R-14), so `ops/api.ts` reads `ops.organizations.get` for the rows of the page, 4 at a time (25 reads for a full page). Follow-up 1 removes them.
2. **The `If-Match` value is built from the body.** `ApiClient.request` returns no response headers, so `entitlementEtag` builds `W/"<version>-<updatedAt in epoch ms>"`, the format of the server's `entitlementEtag`. The API spec checks every `If-Match` the console sends with the server's own `entitlementEtag` and `ifMatchOf` from `apps/server/dist`, run in a child Node process (the spec loader cannot load the CommonJS build that requires the ESM contract package). Follow-up 2.
3. **The API spec answers the SaaS routes with `page.route`.** The API E2E stack runs single tenancy (as M2-S11 found). `e2e/api-only/ops-organizations.spec.js` checks with the real api that the six read routes the console uses answer 409 `single_tenancy` and that the console says so; the multi tenancy flows run against a small service in the spec that parses every request and answer with the schemas of `@mscd/shared`, follows the machine of `MACHINES['organization.status']` and checks `If-Match` as above, with the operator's multi tenancy rights added to `GET /me`. The real multi tenancy run is M2-S13's SaaS smoke.
4. **`e2e/screens/ops.spec.js` (M2-16's spec, owned here by `ops*.spec.js`):** six rows after "Create" (five sample organisations and the new one), and the time zone select is `.first()` because the dialog now has a second select. No check was removed.
5. **The list drops M2-16's Members, Management systems and Created columns.** Keeping them beside the columns the brief adds would make eleven columns in one card, so the list keeps what an operator scans for and the drawer holds the rest. Members became the Users column ("86 of 100"). The systems count and the created date are in the drawer: Overview shows both, Entitlements shows the systems against their limit. A Systems column "used of limit" can return once the list item carries `maxManagementSystems` (follow-up 1).

## Follow-ups

1. **Contract and server (orchestrator; `packages/shared/src/api/ops.ts` and `apps/server/src/modules/ops/organizations.service.ts`, M2-S09's files):** add `maxUsers` and `maxManagementSystems` (nullable) to `OpsOrganizationItem`, read from the entitlement row the list query already joins (`e.max_users`, `e.max_management_systems`). Then `ops/api.ts` drops `DETAIL_READS` and the detail reads, and `fromOrg` takes the field. With `maxManagementSystems` the list can show a Systems column "used of limit" again (deviation 5).
2. **M2-01 owner (`apps/web/src/data/api/ApiClient.ts`):** return the `ETag` header of a success in `ApiResult` (for example `etag?: string`). Then `ops/api.ts` takes it in `entitlement()` and `setEntitlement()` instead of `entitlementEtag`.
3. **Server (M2-S11's `ops/domains/domains.service.ts`):** `organization_archived` and `domain_changed` carry no `messages`; the console shows its own text for both. Adding both languages on the server would let every client show them.
4. **`docs/saas/operator.md` (M2-S09; M2-S13 before go-live):** "Change the status" says "open the organisation and choose Change status". In the console it is Organisations, "Manage", the Status tab, then "Suspend", "Reactivate", "Start offboarding" or "Archive". `docs/saas/entitlements.md` and `docs/saas/sign-in.md` can name the Entitlements and Domains tabs as the way to change a plan and verify a domain.
5. **M2-S13:** the SaaS smoke covers the console against a real multi tenancy stack (create Alpha with `standard` and Beta with `trial`, verify a domain through the mock DNS); `data-org-drawer`, `data-domain`, `data-domain-outcome`, `data-entitlement-form` and `data-entitlement-version` are stable hooks for it.
6. **D-S5 (M2-S09 follow-up 8):** nothing archives an organisation at the end of the 30 days; the Status tab says when they end and asks the operator to archive.
7. **M2-17:** no new text uses "gate"; the console's labels are in `ops/org-text.ts` and `ops/text.ts`.
8. **Shared tests owned by the orchestrator:** `test/screens/host.test.tsx` and `test/api/controller.test.ts` need no change (the screen's definition, `meta.json` and page actions are unchanged), and pass.

## Review fixes

Two minor findings of the independent review, fixed on 29 October 2026.

1. **A preset picked for an organisation that has an entitlement took the first day of that entitlement.** For an ended plan (sample bsd, from 16 Sep 2025) the new "standard" plan ended on 15 Sep 2026, already past. `planPicked` in `ops/org-model.ts` now sets the first day to today when a preset replaces custom limits, and back to the row's first day when the operator returns to custom limits; the Entitlements tab applies it to every change of the picker. The unit test "a preset picked for an organisation whose plan has ended starts today" covers it, and the sample spec checks that picking "standard" for ndt shows the sample's today (29 Sep 2026) and "The preset runs until 28 Sep 2027." before the operator types another day.
2. **The removed list columns were not recorded.** Deviation 5 now gives the removal of Members, Management systems and Created and where that information is shown; follow-up 1 notes the Systems column that can return. The unused texts `colPlan`, `colMembers`, `colSystems` and `colCreated` of `ops/text.ts` are removed.
