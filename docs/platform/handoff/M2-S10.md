# M2-S10 handoff: per-organisation entitlements

In multi tenancy the effective licence of each organisation is now its `platform.entitlement` row. The operator sets it from a plan preset of `license.plans`, from explicit limits, or by uploading a signed licence; every process reads it through a cache of up to 60 seconds that a change notice clears at once. Single tenancy keeps the signed licence file as before.

## Deviations

1. **`If-Match: *` creates the first row.** An organisation without an entitlement has no ETag to send, so `*` replaces any row and creates a missing one; any other tag is 412 there.
2. **428 is the `precondition-failed` problem with status 428** and messageKey `if_match_required`, since the contract adds no problem slug (S-3). The contract harness accepts it (428 is in the route's errors).
3. **The listener runs only with tenancy `multi`.** Single tenancy writes no entitlement and changes no organisation through operator routes, so its api and worker processes open no extra connection. M2-S09 changes `TenantChangeListener.enabled` if it needs notices in single tenancy.
4. **Tenant Admins get the expiry email through their notice.** The `licence_expiring` notice is emailed by `notifications.dispatch`, in the user's language, and `license.check` (60, 30, 7 days) and `entitlement.expiry` (30, 7 days) share it, so a Tenant Admin gets one notice and one email per day whichever job runs first. Only the operators get the `entitlement_expiring` account email.
5. **A row from a signed licence is the licence.** Its limits are read from the row; the stored licence gives only the id, key id and binding shown on the Licence screen. A licence that would stop verifying later (for example after a key is withdrawn from the build) no longer turns the organisation read-only; the operator changes the row instead.
6. **A row without an end date** is evaluated as valid until `9999-12-31` without grace, so `mscd_licence_days_left` reports about 2.9 million days for it and `LicenceExpiringSoon` stays quiet.
7. **The operator read writes the backfill.** `ops.entitlements.get` and `license entitlements show` read the licence first, so an organisation with only a pre-M2-S10 licence shows its new row at once instead of 404.
8. **Explicit limits of the command keep the current values** of the options left out, become source `manual`, and take the plan name only from `--plan` (a preset's name would describe other limits).
9. **The trial preset has 7 days of grace.** D-S4 names users, systems and validity only; `standard` keeps the default 30.
10. **A run missed by more than a day sends nothing for that day.** The ledger rules of M2-06 apply: a tick catches up only the current and the previous local date, one run per job, and deletes ledger rows after 14 days, so an outage longer than a day can skip a reminder day. The tests show the catch-up of the day before.
11. **Operator emails are retried only when none of the run's emails went out.** `AccountMailer.send` answers false on any SMTP error and never throws. When every operator email of a run failed, the job hands the run back to the tick by deleting its ledger row, the way the tick handles a send the queue drops, and the tick runs it again every hour while its date is the current or the previous local date. Nobody got the email, so nobody gets it twice, and the Tenant Admin's notice is written once. When some emails went out and some did not, a second run would email again the operators who got it, so the row stays, the job logs an error and the others miss that reminder. Failing the job for pg-boss to retry was not used: its retries come within seconds (`retryDelay` 1 with backoff), which does not outlast a mail server outage, and they would repeat the emails already sent. A record per recipient would need a table, which is outside this package (no migration in its Owns list). `docs/saas/entitlements.md` names the gap under "Reminders before the last day".
