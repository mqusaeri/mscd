# WP-30 handoff: security, RBAC and contract test suite

## What was built

All suites run on the full api application of run mode `api` (`ApiModule`, `createHttpApplication`) on a copy of the demo template, with users that hold exactly one role of F.6 and sessions written through `SessionService`. The shared harness is `apps/server/test/int/contract/harness.ts`: `createFullApp`, fixture users per role, `sessionFor` and `demoSession`, request inputs built from the hand-written schema examples of the route table (`exampleInput`), and `callRoute`, which checks every answer against its `RouteDef` (declared status codes, the response schema, `Problem` for errors, the F.13 headers on file routes).

## Follow-ups

- WP-33 (CI): the WP-30 suites need Docker (PostgreSQL, and SeaweedFS for `security/files.test.ts`); they run in the `integration` job with the rest of `test:int`.
- Product owner: Top Management sees its own pending items with holder and date; all other pending work shows as Unassigned in the item lists, the phase activities and the register lists (and without review, next-due, target or next-review dates), the audit preparation, cycle and drift lists show only Top Management's own rows, while the totals are unchanged. Past facts stay (who implemented or verified a corrective action, verification dates, audit and review dates). One rule for blocker text: the blocker note of other people's requirements is removed like the blocker text of their phase activities, so the readiness export shows Top Management no per-item blocker text for items it does not hold. The kept fields are pinned in `owner-scope.test.ts` (`PAST_PERSON_KEYS`: `implementedBy`, `verifiedBy`; `PAST_DATE_KEYS`: `implementedAt`, `verifiedAt`, `heldAt`, `raisedAt`, `detectedAt`, `assessedAt`, `updatedAt`, `scheduledAt`, `plannedAt`, and `date` of a verified activity); any other key naming someone else, or any other date on a record whose holder is hidden, fails the every-GET-route check. If the product owner treats `scheduledAt` of an audit activity or `plannedAt` of a management review as a due date, remove it from that list and blank it in the list reads. If the screen should instead hide the item lists entirely, `projectSnapshot` is the one place to change.
